# Metari development instructions

## Source of truth and deployment
- Work directly in this GitHub repository. Host previews and production on the existing Metari Vercel project.
- Do not use Lovable for development, hosting, generated assets, databases, or runtime dependencies.
- This is a static HTML/CSS/JavaScript site. Preserve the existing architecture unless Steven explicitly approves a migration.
- Preserve `/index.html`, `/1x/`, existing assets, domain configuration, and production behavior when working on `/micro1/`.
- Develop on a feature branch and open a pull request. Keep production unchanged until Steven approves publishing.
- Review Vercel deployment status for the exact head commit. Never claim a deployment is live based only on a queued build.

## micro1 partnership concept
- `/micro1/index.html` is a client-side simulation, not a live command center or a micro1 integration.
- Clearly distinguish published micro1 capabilities, proposed Metari capabilities, fictional buyers, and simulated outcomes.
- No partnership, endorsement, customer relationship, purchased facility, active hardware inventory, pricing, throughput, or model performance may be invented.
- The current micro1 capability source is https://www.micro1.ai/robotics. Reverify public claims before external delivery.
- Healthcare and senior living scenes are controlled mock environments. Do not imply patient care, resident care, or medical validation.
- Operational traces show scripted system events, not private model reasoning.
- No public navigation link to the concept without approval. Noindex is not authentication or access control.
- Reuse the actual Metari assets. Use root-relative URLs so routes work with and without trailing slashes.
- Use the existing near-black and green visual language. No em dashes in new visible copy.

## Quality checks
- Verify run, pause/resume, reset, replay, domain selection, rotation, zoom, zone selection, property-map toggle, planner changes, and local brief download.
- Verify 1440, 1024, 768, 390, and 360 pixel layouts and reduced-motion behavior. Check console errors and actual deployment asset responses.
- All output counters must reconcile. No paid work order, form submission, email, or external API request is generated by the demo.
- Keep test results and outstanding limitations explicit. Do not claim another coding agent ran unless it actually ran.
